🗺️ خريطة مشروع Ticket Classifier

دليل شامل لفهم المشروع: بنيته، تدفقه، حالته الحالية، وتقييمه

1. إيه هو المشروع ده؟

ده مشروع تصنيف تذاكر الدعم الفني (Support Tickets) باستخدام LLM. العميل بيبعت رسالة شكوى/طلب، والموديل بيطلعلك JSON منظم فيه:

  • category (الفئة): technical / account / delivery / billing / subscription
  • sentiment (المشاعر): positive / negative / neutral
  • urgency (الأولوية): low / medium / high
  • summary (ملخص قصير)

المشروع جزء من كورس DEPI Agentic، وبيعلّم مفاهيم أساسية: Structured Generation, Prompt Engineering, Evaluation, Inference من الصفر.

4. شرح كل موديول باختصار

📝 prompts/classifier_prompt.py

الدالة build_ticket_classifier() بترجع prompt فيه: دور الموديل، تعريف كل فئة، أمثلة few-shot، وبعدين التذكرة المطلوب تصنيفها. دي نقطة قوة — الـ prompt متعرف كويس.

🏗️ structured/

schema.py بيحدد الشكل بـ pydantic + Literal types. generator.py + outline_adapter.py بيوصلوا الموديل بمكتبة outlines اللي بتعمل constrained decoding (الموديل مش هيقدر يطلع JSON غلط). parser.py بيحلل وبيتأكد.

⚙️ src/inference/

ده "من الصفر": بتحمّل الموديل والـ tokenizer، وبتعمل الحلقة بنفسك — tokenize، لفّ على max_new_token، طبّق temperature/top-k/top-p/logit bias، اختار التوكن، وقف عند EOS أو stop sequence. معمول للتعليم أكتر من الاستخدام العملي.

📊 evaluation/

TicketEvaluator بياخد كل صف في الداتا، يجيب prompt، يولد، يبارس، ويقارن بالنتيجة الصح، ويخزن النتيجة في EvaluationModel حتى لو فشلت (مع رسالة error مفصلة). وبعدين metrics.py بيحسب: validity rate, category/sentiment/urgency accuracy, overall success rate, failure count.

🔌 LLM/

محاولات لكتابة abstractions للـ LLM. config.py بيقرا api_key/base_url/model من env. openai.py كلاس OpenAiCompatible. فيه مشاكل (تحت).

5. التقييم — أنا شايفه إزاي؟ ⭐

✅ نقاط قوة

  • فكرة المشروع واضحة ومتكاملة: data → prompt → structured generation → parsing → evaluation.
  • تقسيمات ملفات منطقية (prompts / structured / evaluation / inference).
  • استخدام pydantic + Literal للـ schema حاجة ممتازة.
  • الـ evaluator بيفصل "الـ success/failure" عن "الـ correctness" — مفهوم صح ومتقدم.
  • وجود ملف PROJECT_LEARNING_GUIDE.md توثيق ضخم — ده عبقري للدراسة.
  • تجربة الـ inference من الصفر بـ temperature/top-k/top-p — فهم عميق.

⚠️ نقاط ضعف ومشاكل حاليا

  • 🔴 استيرادات مكسورة (imports): ملفات كتير بتستخدم from base import، from schema import، from models import، from src... بدل relative imports — ده ممكن يخلي التشغيل يغلط حسب المكان اللي انت فيه.
  • LLM/Model.py فاضي بس openai.py بيستورد منه GenerationRequest ← هيفتحش.
  • structured/parser.py بيستورد from schema import TicketSchema — لازم تكون from .schema أو from structured.schema.
  • evaluation/evaluator.py بيستخدم from models import بدل from .models.
  • src/inference/config.py بيطبع اسم الموديل عند الاستيراد (side effect مش حلو).
  • الداتا صغيرة جدًا (10 صفوف) — التقييم مش هيكون موثوق.
  • tests/test_evaluation.py فاضي، ومفيش unit tests حقيقية (pytest موجود بس الملفات فاضية/سكربتات).
  • LLM/api.py بيستخدم client.responses.create وres.output_text — ده API تجريبي ممكن متكونش مدعومة في كل الإصدارات.
  • tests/test.py بيستورد from Src.inference... وfrom Structured... (case غلط) كـ fallback — مش شغالة على Linux (لكن إحنا على Windows case-insensitive عشان كده بتشتغل).
  • LLM/config.py بيتوقع env vars اسمها api_key, base_url, model بس .env فيه Model وDataSet بس ← مش متطابق.

🎯 تقييم عام

المشروع فكرة ممتازة وهيكل كويس جدًا للمبتدئين في LLM engineering، وبيعلم مفاهيم محترمة (structured output, evaluation, inference من الصفر). لكنه مش متكامل/مش شغال 100% بسبب مشاكل الاستيراد والملفات الفاضية وعدم تطابق الـ env. تقييم من 5: 3.5/5 للتعليم، 2/5 للاستخدام العملي حاليًا.

6. نصايح لإصلاح وترتيب المشروع

  1. وحّد الاستيرادات: استخدم relative imports جوا كل package (from .schema import، from .models import) أو خلي ME هو الـ package root.
  2. املأ LLM/Model.py بتعريف GenerationRequest وMessage اللي openai.py متوقعهم — أو احذف openai.py لو مش محتاجه.
  3. وحّد أسماء env vars بين .env وLLM/config.py وsrc/inference/config.py.
  4. شيل الـ print على مستوى الـ import في src/inference/config.py.
  5. زوّد الداتا (استخدم dataset تذاكر حقيقي زي customer_support_tickets) وادّيها splits train/test.
  6. اكتب unit tests حقيقية في tests/ لـ parser و metrics والـ decoder functions — واستخدم pytest فعلاً (موجود في .pytest_cache).
  7. املأ tests/test_evaluation.py بتجربة حقيقية للـ evaluator على subset صغير.
  8. أضف README صغير يشرح إزاي تشغّل المشروع من الصفر.
